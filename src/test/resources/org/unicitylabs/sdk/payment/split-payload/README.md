# Split payload cross-SDK vectors

`split_payload.json` is generated by the reference TypeScript SDK
(`state-transition-sdk-js`), commit
`6bd409bcdd2d312c814f7b9b8b91982c2c16253c` (`origin/main`, "Merge pull request
#177 from unicitynetwork/review/long-poll-202610170141"). Rust must reproduce
its burn transaction, split manifest, output commitments and allocation proofs
byte for byte (`tests/split_payload_vectors.rs`).

Two cases, each splitting a JS-minted source token with fixed token type,
salts, recipients (secp256k1 private keys `1..3`), burn state mask and burn
deadline:

- `wrapped_10_into_3_7`: payment data wrapped in an application envelope
  `tag(39050, [1, assets, null])` (defined in the generator only; the SDK has no
  such rule), 10 split into 3 + 7.
- `bare_two_assets`: bare asset collections, two assets split into 60/50 + 40.

The source token carries a wall-clock inclusion proof, so regenerating changes
`sourceToken` (and the values derived from its id only if the mint changes); the
split outputs are a pure function of the recorded inputs.

## Regenerating

```sh
cd ../state-transition-sdk-js
git worktree add --detach /tmp/js-vec 6bd409bcdd2d312c814f7b9b8b91982c2c16253c
cd /tmp/js-vec && npm ci
cp <this dir>/generate-split-vector.ts tests/functional/payment/GenerateRustSplitVectorTest.ts
RUST_SPLIT_VECTOR_OUT=<this dir>/split_payload.json \
  npx jest --testPathPatterns=GenerateRustSplitVectorTest --collectCoverage=false
```
